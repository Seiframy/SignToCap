# SignToCap GPU Control Center

From the workspace on Windows, launch SignToCap with `python -B .\phase3\desktop.py --open`. It opens the same localhost app used for replay and local evidence. For a different preparation allowance, add `--setup-minutes` with a value from 1 to 14. The default is 10 minutes from RunPod’s original start time.

## Run a rehearsal

1. In **GPU Control Center**, use a RunPod API key scoped to `pods:read` and `pods:write`. Start one Pod in the RunPod console. SignToCap verifies one supported GPU, the EUR-IS-1 data center and the configured team network volume at `/workspace`. See [GPU profiles](gpu_profiles.json) for supported models.
2. Select the running Pod or enter a spending ceiling for **Automatic under ceiling**. The app adds a container disk allowance to RunPod’s hourly compute quote using the reported disk size and the published $0.10/GB/month rate. It budgets for a 28-day month and rounds up to the next $0.001/hour. Enter an override if your verified rate is higher. RunPod bills the existing shared network volume separately. An L4 or RTX 4090 selected by name can use its configured ceiling of $0.70 or $0.90 per hour. L40S requires an explicit ceiling. [RunPod Pod API](https://docs.runpod.io/api-reference-v2/pods/get-a-pod) · [RunPod billing](https://docs.runpod.io/accounts-billing/billing)
3. Click **Attach & Prepare GPU**. Review the exact Pod and hourly rate and authorize its shutdown. The Windows watchdog locks the session to that generation and uses the original RunPod start time. Until attachment, use the RunPod console to stop a manually started Pod. [RunPod state transitions](https://docs.runpod.io/api-reference-v2/pods/trigger-a-pod-state-transition)
4. The app obtains direct SSH details from RunPod and tries its authenticated Pod command endpoint for the SSH host key. If the endpoint is unavailable, the app provides one command to run in the selected Pod’s **RunPod web terminal**. Paste the complete output into SignToCap and confirm its source. Use the Windows SSH identity already installed for this Pod, such as a default OpenSSH key or an unlocked ssh-agent identity. The app pins the public key, checks the Pod and mount, stages and verifies the worker, and starts the Pod watchdog before loading Uni-Sign. If the shared pose cache is incomplete and the verified Windows copies are available, it stages those copies into the isolated session directory. [RunPod authenticated command API](https://docs.runpod.io/api-reference-v2/pods/run-a-command-in-a-pod)
5. Once the model is ready, enable **Record Test on start** if needed and click **Start Live Test**. Grant browser camera permission. Click **Commit sentence** or press **Ctrl+Enter** after each completed turn. **F8** starts or ends a test when the app has focus. Captured test video, events, and evidence stay in this browser profile. The worker receives sampled frames over SSH for inference.
6. Use **End Test and Stop GPU** for a normal finish or **Stop GPU** at any point during a guarded session. The test lasts at most 60 seconds, and the Windows watchdog stops after 20 seconds without the owning browser’s heartbeat once ready. Both watchdogs begin shutdown by 14m45s from the actual Pod start and verify state through RunPod. If the app reports **STOP UNVERIFIED**, open **RunPod console → Pods**, select the displayed Pod, click **Stop**, and verify **Exited**. The same app button reconciles an unresolved shutdown when the console and API confirm the state. Actual provider transition and billing times can differ from the watchdog deadlines.
7. Select the saved test under **Test Recording** to play it, or use **Save video and evidence files** to export the recording, available caption overlay and JSON. Evidence uses the same localhost port and browser profile as the original app.

RunPod can permit Start and Stop while denying command execution to the same key. When it blocks the authenticated host-key lookup, use the single guided web-terminal dialog. The app passes the scoped key over verified SSH to the detached Pod watchdog in memory so it can stop the exact generation if the laptop disconnects.

## Engineering decision

Keep LoRA on hold. Run the separate paired Phase 3 benchmark and have an ASL-qualified reviewer compare full-rate publisher/fresh outputs, the 3 fps arm, and explicit webcam turns. A drop isolated to fresh poses calls for extraction work. A drop at 3 fps calls for capture/inference work. Strong bounded outputs with unstable replay or poor boundaries call for controller and segmentation work first. Reconsider streaming-aware adaptation only if completed-sentence meaning is adequate and streaming-specific errors persist. Keep all evaluation clips and personal rehearsals outside training.
