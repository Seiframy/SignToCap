# Model, data and training validation

Verified against author repositories, artifact pages and papers on November 26, 2026. These checks inspected source and artifact metadata. Model loading, archive contents, and inference performance remain to be tested.

## Baseline choice

Start with the released **Uni-Sign pose-only How2Sign checkpoint** and measure offline and streaming replay on the same videos. Training is conditional on the failure mode. The original paper reports How2Sign BLEU-4 14.5 and BLEURT 48.6 for pose only and 14.9 and 49.4 for RGB plus pose. SHuBERT reports 16.2 and 49.9 in its own offline evaluation. These published results provide context for the experiment. The SHuBERT paper identifies 72.4% overlap between the YouTube-ASL pretraining corpus and OpenASL test material and flags the Uni-Sign OpenASL result accordingly. It uses BF16, 4 beams and up to 100 new tokens. Capture one parity result before reducing beams or token budget. Divide x by frame width and y by frame height before passing to upstream normalization. Admit one tracked signer and handle missing detections before invoking the model. For strict replay parity, use `ds.collate_fn([ds[0]])` with `S2T_Dataset_online`. Use deterministic input sampling within the 256-frame default maximum because the upstream loader samples randomly above that cap. ## Data and validation splits

Use approved candidate webcam examples and available labeled How2Sign clips for the first offline/streaming comparison. The official manually realigned sentence metadata are available separately for train, validation and test. The official downloadable sentence RGB clips were cut with the original timestamps, so use manually realigned annotations with their source video timeline whenever evaluating true boundaries or constructing training prefixes. The official dataset site also distributes body/face/hand keypoints. The Uni-Sign publisher provides a separate model-compatible RTMPose archive. For adaptation, start with up to 1,024 eligible official-train sentences and 128 official-validation examples, capped per source video and stratified by duration. Match the manually realigned rows to pose filenames by ID, verify temporal coverage against a probe clip, and log unmatched or ambiguous rows. ## Training decision and bounded experiment

1. If reference clips work and streaming meets its target, ship the frozen checkpoint for the research demo. If the oracle split works and live quality drops mostly around boundaries, calibrate pause/motion and commitment rules first. A small boundary model fitted to human-aligned end timestamps is an option only after a persistent boundary-only failure. If offline webcam meaning is weak, inspect tracking and normalization first and compare an alternate translator before proposing decoder adaptation.
2. If correctly bounded full clips work and partial results remain late or unstable, run a conditional projection adaptation. Freeze the pose GCN and temporal GCN, input embeddings and translation model. Train `pose_proj` (1024 × 768 plus bias, 787,200 parameters). Escalate to projection plus optional rank-8 LoRA on mT5 decoder cross-attention q/v only if projection-only shows a reproducible gain worth iterating on. Wrap `model.mt5_model` after strict load with `peft==0.11.1`, alpha 16, dropout 0.05, using a full-match target regex `decoder\.block\.\d+\.layer\.1\.EncDecAttention\.(q|v)`. Expect 24 matched projections and 294,912 additional parameters. Keep the untied output head frozen and keep frozen pose normalization modules in eval mode during adaptation. [Uni-Sign projection](https://github.com/ZechengLi19/Uni-Sign/blob/eed438bcb49e30405cd6ccdfcccca330c134e830/models.py#L65) · [mT5 config](https://huggingface.co/google/mt5-base/blob/2eb15465c5dd7f72a8f7984306ad05ebc3dd1e1f/config.json) · [mT5 implementation](https://github.com/huggingface/transformers/blob/v4.40.0/src/transformers/models/mt5/modeling_mt5.py) · [PEFT release](https://github.com/huggingface/peft/releases/tag/v0.11.1)
3. Mix complete sentence input with lexical targets documented as recoverable from the specific partial visual input. A practical first augmentation takes a completed sentence and some following signing from the same aligned source and supervises only the completed sentence. A partial current sentence receives an English label only when an ASL reviewer verifies the evidence available at that cutoff. Define cutoffs in time or frames and preserve full text labels for complete sentences. Route idle and unknown activity through the boundary/gating layer so missing evidence is never silently treated as a valid text target.
4. Proposed controls are seed 42, one GPU, BF16 autocast, FP32 trainable weights, AdamW, projection LR 2e-4, optional LoRA LR 1e-4, weight decay 0.01, one clip per microbatch, accumulation 16, 256 source frames, 50 target tokens, gradient clipping 1.0 and up to 128 optimizer steps. Evaluate and save every 32 optimizer steps. Smoke-test data, finite gradients, and restart at 10 optimizer steps. Time measured steps plus evaluation/checkpoint I/O before projecting completion cost. Projection-only still requires gradients through mT5 to the projection. Check actual peak allocated and reserved GPU memory before committing a longer run.
5. Keep adaptation only if the frozen baseline is beaten on the predeclared latency/stability failure and full-sentence semantics meet the paired non-regression gate. Compare multiple reviewed streams and retain no-sign behavior. Save adapter/projection weights, optimizer state, RNG, run config, manifest hashes and source/model revisions separately, and test resume before relying on persistence.

## Alternatives and rights

- The author-hosted SHuBERT Space is an offline quality comparator for approved shareable clips or its bundled examples. It references a ByT5 stack, an encoder at `models/checkpoint_836_400000.pt`, and a translator at `models/checkpoint-11625`. Its startup explicitly requires `HF_TOKEN` and describes a private weight repo. The model card is publicly visible and labeled MIT, but anonymous access to the complete stack could not be established. The author GitHub links encoder and DINOv2 hand/face weights and marks downstream fine-tuning TODO. Its hand/face RGB feature extraction also adds work. [Space model initialization](https://huggingface.co/spaces/ShesterG/TTIC-SHuBERT-ASLVideo-to-EnglishText/blob/main/app.py) · [Author README](https://github.com/ShesterG/SHuBERT#2-model-weights) · [Model card](https://huggingface.co/ShesterG/SHuBERT)
- MoGloss is a recent pose-only ASL candidate with stronger comparisons in the authors’ reproduction, but the author's release page did not establish a downloadable translation checkpoint for the first experiment. [Primary preprint](https://arxiv.org/abs/2611.25333) · [Author data and checkpoint status](https://huggingface.co/datasets/HenryH101/MoGloss)
- How2Sign and the Uni-Sign weights carry CC BY-NC 4.0, and the OpenASL dataset carries CC BY-NC-ND 4.0. The pinned Uni-Sign repository did not present a clear top-level source license in the inspected listing. Verify code, extractor and checkpoint rights separately before commercial use or redistribution. The SHuBERT repo’s MIT label alone does not establish rights for every task checkpoint, third-party artifact, or downstream dataset.
